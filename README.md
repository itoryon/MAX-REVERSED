# MAX REVERSED

> Попытка создать более прозрачный и приватный клиент MAX на основе исследования оригинального Android-приложения.

## 🎯 Цель проекта

**MAX REVERSED** — проект по исследованию Android-клиента MAX и созданию максимально «чистого» варианта клиента.

Основная цель — понять, какие компоненты приложения отвечают за телеметрию, аналитику и сбор данных, и по возможности исключить из клиентской части функции, не необходимые для основной работы приложения.

Мы хотим получить клиент, который:

* не содержит лишней аналитики;
* минимизирует телеметрию;
* не собирает данные без необходимости;
* не содержит ненужных трекеров;
* запрашивает только действительно необходимые разрешения;
* максимально прозрачно взаимодействует с сетью и устройством пользователя.

Проект ориентирован на **приватность, прозрачность и контроль пользователя над своим клиентом**.

---

## 🔍 Что мы делаем

В рамках проекта проводится анализ оригинального Android-клиента MAX.

Основные направления работы:

### 📊 Удаление лишней телеметрии

Мы исследуем компоненты, связанные с:

* аналитикой;
* логированием;
* рекламными идентификаторами;
* диагностикой;
* метриками;
* сторонними SDK.

Задача — определить, какие из этих компонентов действительно необходимы для работы клиента, а какие могут быть отключены или заменены.

---

### 📱 Минимизация доступа к данным устройства

Отдельное внимание уделяется разрешениям и обращениям к Android API.

Проверяются:

* доступ к информации об устройстве;
* сетевое состояние;
* список установленных приложений;
* Advertising ID;
* другие идентификаторы устройства;
* системная информация, не необходимая для работы клиента.

Цель — оставить только тот доступ, который действительно нужен пользователю для работы с конкретной функцией.

---

### 🌐 Прозрачная работа с сетью

Проект также направлен на изучение сетевого взаимодействия клиента.

Мы пытаемся определить:

* какие серверы используются приложением;
* какие запросы необходимы для работы;
* какие запросы относятся к аналитике или телеметрии;
* какие данные передаются клиентом.

В идеале пользователь должен понимать, **что именно его клиент отправляет и зачем**.

## 🔐 Принципы проекта

Мы придерживаемся нескольких простых принципов:

**Минимум данных**
Клиент не должен собирать данные, которые не нужны для его работы.

**Минимум разрешений**
Каждое разрешение должно иметь понятное назначение.

**Прозрачность**
Пользователь должен понимать, какие функции работают и какие данные используются.

**Контроль пользователя**
Функции, связанные с необязательной передачей данных, не должны быть скрыты от пользователя.

**Открытость изменений**
Все изменения относительно исследуемой версии клиента должны быть понятны и доступны для анализа.

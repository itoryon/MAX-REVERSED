# MAX-REVERSED

> Реверс-инжиниринг и патчинг Android-приложения **MAX** (`ru.oneme.app`) с целью
> убрать клиентскую слежку, телеметрию и «предупреждающие» детекты (VPN и пр.),
> сохранив рабочую функциональность мессенджера. Сборка — через GitHub Actions.

**Статус:** идёт Фаза 2. Готовы: CI-сборка через Actions и вырезание телеметрии — myTracker, OneLog, ok.tracer, а также подавление VPN-предупреждения. Все патчи собираются в подписанный APK (проверено в CI). Детали и текущий статус — в [PLAN.md](PLAN.md).

---

## Что это

`MAX` — мессенджер от VK (пакет `ru.oneme.app`, «ONE ME»). Проект берёт официальный APK,
декомпилирует его в smali через [apktool](https://apktool.org), точечно правит байткод,
пересобирает и подписывает своим ключом. Цель — не «взлом», а **прозрачность и контроль
над тем, что приложение делает с устройством и данными пользователя**.

Разобранная версия: **26.29.1** (`versionCode 6808`), `minSdk 26`, `targetSdk 37`, apktool `3.0.2`.

## Цель

Собрать сборку MAX, в которой у пользователя убраны или нейтрализованы:

1. **Аналитика и фингерпринтинг устройства** — myTracker (`com.my.tracker`, ~132 файла),
   OneLog / ok.tracer (`ru.ok.android.onelog`, `ru.ok.tracer`, ~110 файлов), рекламный ID
   (`AdvertisingIdClient`). Именно здесь, а не в «ядре», лежат проверки root/эмулятора
   (`isRooted`, `test-keys`, `Superuser.apk`, `magisk`) — они уходят в телеметрию.
2. **Предупреждения о VPN** — модуль `one.me.sdk.vpn.VpnConnectedWarningDelegate`
   (`VpnConnectedWarningBottomSheet`, `VpnPanelWidget`, `WebAppHasVpnException`),
   который детектит активный VPN и мешает работой/предупреждениями.
3. **Перечисление установленных приложений** — `getInstalledPackages`,
   `queryIntentActivities` (5–7 мест).
4. **Прочий сбор** — доступ к буферу обмена, рекламному ID и т.п., где он не нужен для UX.

Итог — APK, который можно поставить рядом/вместо официального и пользоваться мессенджером
без фонового «стука» о состоянии устройства.

## Чего проект НЕ делает (честно)

- **Не даёт анонимности.** Аккаунт всё равно привязан к номеру телефона, а протокол
  и часть логики зашиты в нативной `libmax.so` (647 КБ, arm64) — её правки в этот трек
  не входят. Сервер по-прежнему знает, кто вы.
- **Не «разблокирует» то, что и так работает.** По результатам статического аудита MAX,
  судя по всему, **не блокирует** запуск на root/VPN жёстко — он это *репортит* в аналитику
  и *предупреждает*. Так что львиная доля ценности — в вырезании телеметрии, а не в «обходе бана».
- **Не обходит Play Integrity / SafetyNet** — их в приложении **нет** (это упрощает задачу).
- **Не трогает серверную сторону.** Всё, что делается на бэкенде MAX, остаётся как есть.

## Важные технические факты (по итогам аудита)

| Область | Что реально нашли |
|---|---|
| Жёсткий root-бан | Не найден. `isRooted`/`test-keys`/`magisk` — только в аналитике (myTracker, ok.tracer) |
| Play Integrity / SafetyNet / аттестация | Отсутствует |
| Самопроверка подписи (anti-tamper) | Не найдена. `getApkContentsSigners` в `qa8.smali` — вычисление хеша подписи (вероятно, для API), не kill-switch. Ресайн локально ничего не ломает |
| VPN-детект | Есть, пользовательский (предупреждения), выключается через делегат |
| Пиннинг сертификатов | OkHttp `CertificatePinner` присутствует; кастомный `InvalidSslIntegrityException` в `one.me.net.ssl` — требует проверки, активны ли пины |
| Нативная защита | Возможна в `libmax.so` — отдельный трек анализа (Frida/native) |
| Обфускация | Пакеты читаемы (`one/me`, `ru/ok`, `com/vk`); часть классов слита в короткие имена (`qa8`, `kde`) |

## ⚠️ Дисклеймер

Проект — для **исследования безопасности, приватности и личного использования** на своих
устройствах. Модификация и распространение чужого проприетарного приложения может нарушать
условия использования MAX и права правообладателя. Пересобранная сборка теряет обновления из
маркета и может сломать часть серверных функций, завязанных на подпись (например, push).
Автор форка ответственности за использование не несёт. Не публикуйте готовые APK без понимания
правовых последствий.

## Сборка

Сборка выполняется на Linux (GitHub Actions / WSL / Docker). **На Windows репозиторий не
собирается и даже не выкачивается целиком** — в нём есть файл `smali_classes2/nul.smali`
(`nul` — зарезервированное имя устройства в Windows, NTFS не даёт его создать).

Пайплайн: `checkout → проверка патчей → apktool b → zipalign → apksigner (свой ключ) → артефакт`.
Каждая сборка проверяется стражем ([.github/scripts/verify-patches.sh](.github/scripts/verify-patches.sh)):
если вырезанная телеметрия/детект вернулись в smali — билд падает.
Подробности и все фазы — в [PLAN.md](PLAN.md).

### Релизы и ручной запуск

APK любой сборки лежит в артефактах run (вкладка Actions). Кроме того:

- **Ручной запуск.** Actions → «Build MAX (patched)» → «Run workflow». Параметры:
  - `publish_release` — публиковать ли GitHub Release (по умолчанию нет, просто артефакт);
  - `release_type` — `prerelease` или `release`;
  - `release_tag` — тег/имя (пусто = авто `build-<номер>`).
- **По тегу.** Пуш тега `v*` (например, `v26.29.1-1`) сам соберёт и опубликует релиз;
  тег с суффиксом через дефис (`-beta`, `-rc`, `-pre`) уходит как pre-release, иначе — обычный.

## Структура репозитория

```
AndroidManifest.xml   манифест (пакет ru.oneme.app)
apktool.yml           метаданные apktool (версия, sdk, doNotCompress)
smali/                dex #1  → байткод
smali_classes2/       dex #2  → байткод (в т.ч. одно me + аналитика)
smali_classes3/       dex #3  → байткод (webrtc, webapp, net/ssl)
res/                  ресурсы
assets/               ассеты (в т.ч. baseline.prof)
lib/                  нативные .so (arm64-v8a, armeabi-v7a, x86, x86_64)
original/ unknown/    служебные файлы apktool
```

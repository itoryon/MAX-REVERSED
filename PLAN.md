# План работ — MAX-REVERSED

Документ для ревью. Здесь: как устроена работа, порядок фаз, критерии готовности каждой.
Правки в код (smali) делаем маленькими коммитами, каждый — «одна правка, одна цель»,
чтобы любой детект можно было включить/выключить и откатить.

Разведано и осознанно НЕ трогаем:
- **VK Push** (`com/vk/push/*`, 326 файлов) — это уведомления, не телеметрия.
- **OpenTelemetry** (2 файла) — без HTTP-экспортёра, наружу ничего не шлёт.
- **RuStore** — функциональный магазин (биллинг/обновления).
- Нет Firebase Analytics / Crashlytics / AppMetrica / Yandex Metrica.
- `WebAppHasVpnException` — в smali нигде не создаётся/не бросается (только ловится для текста ошибки), активной точки для патча нет.

## Модель работы

- **Источник истины — этот репозиторий** (декомпиляция apktool). Патчи = правки smali,
  закоммиченные сюда. GitHub Actions просто пересобирает то, что в репо.
- **Вся работа — на Linux** (Actions/WSL/Docker). Windows отпадает из-за `nul.smali`.
- **Каждая правка изолирована** и помечена (ветка/тег `patch/<тема>`), чтобы собирать
  как «всё сразу», так и выборочно.
- **Ничего не режем вслепую.** Сначала доказываем, что поведение реально есть и мешает,
  потом патчим. Список детектов от разработчика — это гипотеза; аудит уже показал, что
  половины из него (IMEI, IMSI, SIM, MAC, VpnService, Accessibility-абуз, жёсткий root-бан)
  в smali **нет**.
